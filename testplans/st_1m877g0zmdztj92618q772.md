        Subject: p, Kind: OnProject, Role: best.role, System: best.role == "person", Project: p,

### 2. Where the plan node id is (NOT) available

At :2685 the identifiers in scope are ONLY:
- project name `p`
- the feature-rung ref (`missing[0].Ref` / `b.Ref`)
- the Why string
- `oldest[p]` (a time)

**There is no plan id, no issue id, and no `PlansForProject` call in `bootstrap`.**

The plan id is resolved later, at prompt-build time, in `prefill.go:529-540` via `r.Cmds.PlansForProject(ctx, proj.Name)`, gated on `role=="tech_lead" && n.ID=="" && !lane && onSession=="" && day==nil`. It is rendered into the "The plan for this project already exists" section of the dispatch prompt, not interpolated as the Work row's Subject. This is why session s_1m7wb015q6pkgc8n9qdr5d had to `plan.read` p_1m7jg0mgc1zkar1k7jdwjb itself after dispatch.

**Consequence for the dev subtask:** the fix is not a one-liner at :2685. The plan id must be sourced into `bootstrap` (a `PlansForProject`/live-plans lookup added to the missing-rung path) before it can be set as the subject, and the Work row must switch `Kind` to `OnNode`.
